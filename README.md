# 跨平台电商比价 Agent

> 从「同一件商品要在三个 App 里反复搜、还会漏掉券后价」这个真实痛点出发做的比价工具：
> **一次命令，输出京东 / 淘宝 / 天猫 / 什么值得买 四平台的比价报告**，并按店铺可信度排序，而不是单纯按价格排序。

## 为什么不能「直接按最低价排序」

最低价往往来自第三方专营店或来路不明的链接。真正有用的比价结果必须同时回答两件事：
**这个价格可信吗？这个店铺靠谱吗？**

所以这个工具的核心不是爬虫，而是**店铺优先级规则**：

| 平台 | 排序规则 |
|---|---|
| 京东 | 自营 > 旗舰店 > 专营店 |
| 淘宝 | 最低价优先 |
| 天猫 | 旗舰店 > 专营店 > 普通店 |
| 什么值得买 | 神价 / 历史低价聚合 |

## 架构

```
                  ┌────────────────┐
                  │  compare.py    │  编排 + 僵尸进程清理 + 报告渲染
                  └───────┬────────┘
        ┌─────────────┬───┴────────┬──────────────┐
        ▼             ▼            ▼              ▼
   jd_spider     tb_spider     tm_spider     smzdm_spider
   (京东自营)   (淘宝+天猫      (天猫过滤)     (神价聚合)
                 一次抓取内存过滤)
        │             │            │              │
        └─────────────┴────────────┴──────────────┘
                            ▼
                  ┌────────────────────┐
                  │ 统一结果 → 表格报告 │
                  │ + 最低价冠军       │
                  └────────────────────┘
```

**一个关键设计**：淘宝和天猫共用一次抓取，在内存里按店铺类型分流。原因是两个平台登录态互通，抓两次等于多付一次登录成本与风控风险。

## 技术栈

- **Playwright + playwright-stealth**（主力，绕过基础指纹检测）
- **undetected_chromedriver**（备选方案，用于 stealth 失效时的降级）
- **Cookie 持久化**：登录态存 JSON，复用 Chrome profile，避免每次都等人工登录
- Python（编排、清洗、报告渲染）

## 工程上的四个坑（都实际踩过）

1. **僵尸 Chrome 进程导致 Tab Crash**
   连续抓取多个平台后，残留的 chrome.exe / chromedriver.exe 会拖垮浏览器。
   解法：每次采集前 `taskkill /F /IM chrome.exe` 并等待进程退出——粗暴但有效。

2. **登录态失效是分钟级的**
   Cookie 有滑动过期，且部分平台会与设备指纹绑定。解法：Cookie 落地 + 失效检测 + 重新注入，登录等待预留 300 秒。

3. **固定节奏的请求会被限速**
   解法：请求间隔随机化 + 特征扰动，宁可慢一点也不要被封。

4. **列表页价格不可信**
   券后价、满减要进详情页才可见。直接读列表页会得出错误的最低价。

## 运行

```bash
pip install -r requirements.txt
playwright install chromium

# 配置（复制示例文件后填入自己的值）
cp config.example.json config.json

# 首次运行需要人工登录，登录态会被保存
python compare.py "固态硬盘 1TB" 3
```

## 实测

- 人工跨平台比价：**30 分钟以上** → 本工具：**分钟级**
- 覆盖 4 个平台 / 3 类店铺优先级规则 / 9 个模块（约 874 行 Python）
